# 14.01 Sprint Specification - Migração Consolidação v1

## Identificação

**ID:** ISSUE-3365  
**Nome:** Migração Consolidação v1 (UI + Módulo Angular / prismaService)  
**Data:** 24/11/2025  
**Responsável:** a definir (time técnico Prisma / Consolidação)  
**Status:** Em Desenvolvimento  
**Prioridade:** P1-Alta  
**Tipo:** Feature

## Objetivo Principal

Migrar as telas atuais do módulo de Consolidação, hoje em OutSystems, para um novo módulo Angular dentro do Prisma Frontend, consumindo serviços a partir do projeto **prismaService (EntryPoint)**, garantindo a mesma capacidade funcional atual e preparando o terreno para evoluções futuras.

## Escopo Detalhado

### Componentes a Migrar
- Telas de Cadastro (Carteiras, Portfólios, Instrumentos)
- Módulo de Boletas
- Relatórios e Painéis
- Ranking de Portfólios

### Requisitos Funcionais Principais

1. **Migração Completa da UI**
   - Replicar todas as funcionalidades atuais em OutSystems
   - Manter a mesma lógica de negócio
   - Preservar fluxos de trabalho existentes

2. **Integração com Prisma Frontend**
   - Navegação integrada
   - Consistência de design
   - Autenticação unificada

### Critérios de Aceite

- [ ] Todas as telas mapeadas possuem equivalente funcional
- [ ] Navegação integrada ao menu do Prisma
- [ ] Fluxos de cadastro funcionando completamente
- [ ] Relatórios reproduzem resultados idênticos
- [ ] Controle de acesso validado
- [ ] Testes manuais aprovados
- [ ] Code review aprovado

## Riscos e Mitigações

### Riscos Identificados
- Divergência comportamental entre OutSystems e novo módulo
- Possíveis quebras de contrato de API
- Risco de regressão em cálculos e relatórios

### Estratégias de Mitigação
- Mapeamento detalhado de todas as telas
- Testes comparativos extensivos
- Período de validação com usuários-chave

## Próximos Passos

1. Mapeamento detalhado das telas atuais
2. Definição de APIs no prismaService
3. Desenvolvimento incremental
4. Testes de integração
5. Homologação com área de Consolidação

## Observações Importantes

- Manter regras de negócio no backend
- Priorizar reutilização de componentes existentes
- Documentar decisões de design relevantes
