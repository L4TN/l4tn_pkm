# Tonico Chat Service Backend - Resumo do Planejamento Arquitetural

### **1. Abordagem de Lambda Functions**

**Opções Analisadas:**
-  **Micro-Functions**: 1 função por endpoint (15-30 Lambdas) 
-  **Domain-Based**: 1 função por domínio (4-6 Lambdas)  
-  **Monolithic Lambda**: 1 função com router interno ESCOLHIDO

**Justificativa:**
-  **Time pequeno** - complexidade gerenciável
-  **MVP/Startup phase** - velocidade > arquitetura perfeita
-  **Cold starts otimizados** - 1 cold start vs múltiplos
-  **Custos menores** - ~$1.70/mês vs $3.23/mês (micro-functions)
-  **Deploy simples** - um comando vs múltiplos deploys
-  **Debug mais fácil** - logs centralizados

**Evolução Futura:**
- **Quando migrar**: Time >3 pessoas, >10 routes, >40MB package
- **Para onde**: Domain-Based Functions

---

## ️ **Ferramentas de Deploy Escolhidas**

### **Opções Avaliadas:**

#### **AWS Nativo (CodePipeline + CodeBuild)**
- 100% AWS, integração perfeita
- Setup complexo (2-3 horas)
- Interface menos amigável

#### **AWS SAM**
- CloudFormation nativo, controle total
- Muito verboso, curva de aprendizado alta
- Setup demorado (2-3 horas)
- Similar ao Serverless

#### **Serverless Framework** ESCOLHIDO
- Setup rápido (30 minutos)
- YAML simples e limpo
- Comunidade grande (1000+ plugins)
- Multi-cloud (futuro)
- Dependência externa

**Decisão Final:** **Serverless Framework + GitHub Actions**

**Por quê:**
- **Produtividade** - foco no negócio, não na infraestrutura
- **Simplicidade** - um comando: `serverless deploy --stage prod`
- **Evolução gradual** - pode migrar para SAM/CDK futuramente
- **Time pequeno** - não justifica complexidade do SAM

## **Setup de Desenvolvimento Local**

### **Método Atual (Funciona perfeitamente)**
```python
# Debug direto no Python - SEM serverless offline
python lambda_function.py  # Com breakpoints no VSCode
```

**Por que funciona:**
-  **AWS CLI** configurado → credentials em `~/.aws/credentials`
-  **Boto3** usa credentials automaticamente, ele usa as credenciais para chamar os serviços de nuvem
-  **Bedrock Agent** roda na AWS real (não pode ser local)
-  **Chamadas reais** para AWS APIs

**Métodos Alternativos (Opcionais):**
- `serverless offline` - para simular API Gateway
- `sam local` - para simular ambiente Lambda exato

Escolhi seguir com o Serveless Framework

## **Estrutura de Projeto Recomendada**

### **Nome:** `tonico-chat-service-backend`

### **Convenções Python Aplicadas:**
-  **snake_case** para arquivos/variáveis
-  **PascalCase** para classes  
-  **src/** para código principal
-  **tests/** (não test-cases)
-  **docs/** (não doc)
-  **__init__.py** em todos os packages
-  **requirements.txt** para dependências



### **Estrutura Final:**
```
tonico-chat-service-backend/
├── src/
│   ├── lambda_function.py          # Entry point com router
│   ├── routes/                     # Handlers por rota
│   │   ├── webhook_routes.py       # Huggy webhooks
│   │   ├── chat_routes.py          # Chat endpoints
│   │   └── health_routes.py        # Health checks
│   ├── services/                   # Lógica de negócio
│   │   ├── bedrock_service.py      # AWS Bedrock AI
│   │   ├── huggy_service.py        # Huggy API
│   │   └── supabase_service.py     # Database
│   ├── utils/                      # Utilitários
│   │   ├── duplicate_control.py    # Controle duplicatas
│   │   └── helpers.py              # Funções auxiliares
│   └── config/                     # Configurações
│       └── settings.py             # Environment vars
├── tests/                          # Testes organizados
├── docs/                           # Documentação
├── scripts/                        # Scripts deploy
├── requirements.txt                # Dependências
├── .env.example                    # Template config
└── serverless.yml                  # Deploy config
```

## 🚀 **Pipeline CI/CD Planejado**

### **GitHub Actions + Serverless Framework**

**Workflow:**
```yaml
# Branches → Environments
develop → dev
staging → staging  
main → prod
```

**Pipeline Steps:**
1. **Test** - pytest, linting
2. **Deploy** - `serverless deploy --stage {env}`
3. **Verify** - health checks
4. **Notify** - success/failure

**Vantagens:**
-  **Deploy automático** por branch
-  **Rollback simples** - `serverless rollback`
-  **Secrets management** - AWS Systems Manager
-  **Zero downtime** - CloudFormation handles deployment

---

## 🔍 **Descobertas Técnicas Importantes**

### **1. Serverless Framework usa CloudFormation**
-  **Confirmado** - Serverless é wrapper do CloudFormation
-  **Deploy atômico** - tudo ou nada
-  **Rollback automático** - se algo falha
-  **Dependency management** - CloudFormation resolve
-  **Stack visível** no AWS Console

### **2. Debug Local Funciona sem SAM**
-  **AWS CLI** + **Boto3** = chamadas reais AWS
-  **Bedrock Agent** sempre na nuvem
-  **Debug completo** no VSCode
- ❌ **SAM não necessário** para desenvolvimento

### **3. Cold Start Analysis**
```
Monolithic (1 Lambda):    1 cold start  = ~2s
Domain-Based (5 Lambdas):  5 cold starts = ~10s  
Micro-Functions (20):      20 cold starts = ~40s
```
