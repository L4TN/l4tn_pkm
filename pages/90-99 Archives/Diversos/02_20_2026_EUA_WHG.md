Tasks de Ajuste da Arquitetura AWS
🔴 Alta Prioridade (Custo Direto)
[TASK-01] Substituir GitLab Docker Images por Amazon ECR
Mover o registry de imagens Docker do GitLab para o ECR. Isso mantém o tráfego dentro da rede AWS, eliminando custos de transferência de dados de entrada e saída (egress/ingress). Remover também o VPC Interface Endpoint associado ao GitLab. OK 

[TASK-02] Remover um dos dois NAT Gateways
O diagrama mostra dois NAT Gateways nas subnets públicas sem justificativa. Cada NAT Gateway tem custo por hora + por GB processado. Manter apenas um ou nenhum, conforme necessidade real após o TASK-03. 

[TASK-03] Mover o ECS Fargate para Subnet Pública
Somente o banco de dados (RDS) precisa estar na subnet privada. Mover o Fargate para subnet pública elimina a dependência de NAT Gateway para o tráfego de saída do Fargate, reduzindo custos significativamente.

🟡 Média Prioridade (Boas Práticas / Configuração)
[TASK-04] Revisar e remover VPC Interface Endpoints desnecessários
Com o ECR dentro da AWS e o Fargate em subnet pública, os VPC Interface Endpoints devem ser revisados. Manter apenas os necessários (ex: Secrets Manager, CloudWatch), pois cada endpoint tem custo por hora.

[TASK-05] Definir política de backup do RDS
O banco RDS PostgreSQL está atualmente sem política de backup definida. Alinhar com o cliente retenção (ex: 7, 14 ou 30 dias), janela de manutenção e estratégia de snapshot.

[TASK-06] Configurar DNS — verificar se cliente já possui ou trazer para Route 53
Verificar se o cliente já tem DNS externo gerenciado. Caso não tenha, provisionar o Amazon Route 53 para gerenciar o domínio seuarmazemdrop.com.br dentro da AWS, simplificando a gestão junto ao CloudFront e ACM.

🟢 Baixa Prioridade (Documentação / Revisão)
[TASK-07] Documentar e revisar retenção do CloudWatch Logs
Atualmente configurado em 7 dias. Validar se atende aos requisitos do cliente (compliance, auditoria). Ajustar para 30/90 dias se necessário, considerando o impacto no custo de armazenamento.

[TASK-08] Revisar estimativa de custo por ambiente
A arquitetura atual pode ultrapassar R$2k/mês por ambiente. Após aplicar os ajustes acima, refazer o sizing e a estimativa de custo (usando AWS Pricing Calculator) para prod, staging e dev separadamente.
