# Checklists operacionais

## Deploy / Release

- [ ] Testes passando localmente
- [ ] PR revisado (ao menos 1 aprovação)
- [ ] Variáveis de ambiente conferidas no ambiente alvo
- [ ] Backup ou rollback planejado se necessário
- [ ] Comunicar equipe/cliente antes de subir

## Revisão de PR

- [ ] O que a PR resolve? (contexto claro na descrição)
- [ ] Lógica faz sentido end-to-end?
- [ ] Edge cases cobertos?
- [ ] Sem segredos/tokens expostos
- [ ] Nomes de variáveis e funções claros

## Incidente (quando algo quebra)

- [ ] Identificar sintoma (o que o usuário vê)
- [ ] Identificar escopo (quantos afetados, qual ambiente)
- [ ] Comunicar stakeholders com ETA inicial
- [ ] Corrigir ou reverter
- [ ] Post-mortem curto: o que aconteceu + como evitar

## Onboarding de projeto / cliente

- [ ] Acesso aos ambientes (dev/staging/prod)
- [ ] Repositórios e branches principais
- [ ] Credenciais e secrets
- [ ] Quem é o PO / quem aprova?
- [ ] Canal de comunicação definido
- [ ] Primeira task pequena para validar o setup
